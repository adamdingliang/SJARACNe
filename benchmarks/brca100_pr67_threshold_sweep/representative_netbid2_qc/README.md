## Inputs and provenance

NetBID2 QC was run on each arm's final, post-DPI consensus network. For every matched seed, SJARACNe first applied the arm-specific AP-MI cutoff and then DPI pruning with `epsilon = 0`. The 100 post-DPI seed-level adjacencies were consolidated with the unchanged consensus-network cutoff `p = 1e-5`. The only swept parameter was the per-subsample PR67 threshold.

The HTML files were copied byte-for-byte from these paths relative to the live
sweep work root:

```text
results/p1e-03/tf/netbid2_qc_html/TF_netQC.html
results/p5e-04/sig/netbid2_qc_html/SIG_netQC.html
```

The corresponding consensus-network SHA-256 values recorded by the benchmark manifests are:

- `p = 1e-3`, TF: `04e5363da1cad3a8715c883249986dd3729c464eb483e6993d650717332ca9aa`
- `p = 5e-4`, SIG: `ef081d1b0696e2e225e788f3e84ba44a557dcb1342783f4b76169dbf7ac2a518`

The pinned QC environment was:

- R 4.4.3 (2025-02-28)
- NetBID2 2.2.0, remote commit `5defa454d600b94f5dd6d1f9f4428f99759a6821`
- igraph 2.3.3

See the sweep's committed provenance manifests and result tables in the parent directory for the complete run specification and all threshold arms.

## Download and open

GitHub may display HTML as source instead of rendering it. Download the report (use **Download raw file** on GitHub), verify it locally with `sha256sum -c SHA256SUMS`, and open the downloaded `.html` file in a web browser. Each report preserves the generated bytes and does not require the original WSL result directory. The standard R Markdown template does, however, attempt to load MathJax from `https://mathjax.rstudio.com`; offline viewing may therefore omit MathJax rendering.

These reports are representative network-QC views, not biological validation. They describe topology and driver-target structure after thresholding, DPI, and consensus construction; they do not establish edge truth, control the final-network FDR, or demonstrate downstream activity robustness.
